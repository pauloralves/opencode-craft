# Interview Angle & Storytelling

When this skill is invoked (via `@interview-angle` or when the user asks how to talk about this project or code in an interview):

### 1. The STAR Architectural Framing
Structure the insight around how a Senior/Staff candidate explains decisions:
- **Context/Constraint**: What was the tricky problem or constraint (e.g., Apple Silicon Metal limitations, memory bounds, latency requirements)?
- **Options Considered**: Briefly contrast 2 realistic approaches.
- **Decision & Trade-offs**: Why we picked this path, and what we sacrificed (e.g., compile-time simplicity vs runtime throughput).
- **Outcome & Metrics**: How we verify it works (benchmarks, quality metrics, test coverage).

### 2. Antagonistic / Probing Questions
Give the user 1 or 2 probing questions a good technical interviewer might ask about this specific part of the system, along with how to defend the design confidently.

### 3. Red Flags to Avoid
Warn against rookie explanations or common misconceptions that raise eyebrows during technical rounds.
